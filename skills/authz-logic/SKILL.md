# 越权与业务逻辑（Authz & Logic）

这类漏洞不在 WAF 签名里，靠"把合法功能用错"。核心方法：**两账号对照 + 参数枚举 + 状态机推演**。

## 准备：双身份基线

1. 建两个低权限账号 A/B（同角色）与一个高权限账号 H（如可得）。
2. 对同一业务对象，分别用 A/B/H 发同一请求，记录三份响应。
3. 差异即为授权判定点：谁被拒绝、谁被放行、拒绝发生在网关还是业务层。

## IDOR / BOLA（对象级越权）

- 枚举所有带对象标识的请求：`/api/users/{id}`、`/orders/{uuid}`、`?account_id=`、GraphQL `node(id:)`。
- 用 B 的凭据访问 A 的对象；再试数字 ID 遍历、UUID 不可预测性、批量接口（`ids[]`）。
- 变体：嵌套资源（`/users/1/orders/2`）、写操作（PUT/PATCH/DELETE）、导出/下载、附件、邀请。
- 判断"真越权"：返回 200 且含他人数据；仅 200 空壳不算。

## BFLA（功能级越权）

- 低权限账号直接调用管理员接口（`/admin/*`、`/internal/*`、`/api/v1/admin`）。
- 方法覆盖：`X-HTTP-Method-Override`、`_method=PUT`、大小写路径、尾斜杠、版本降级（`/v2` → `/v1`）。

## 批量赋值 / Mass Assignment

- 在合法更新请求中注入：`role`、`is_admin`、`verified`、`balance`、`owner_id`、`tenant_id`、`permissions`。
- 结合响应差分：字段是否被接受（返回体/重放 GET）。

## 业务逻辑

- **价格/数量**：负数量、0 元、小数精度、货币换算、优惠券叠加、退款超额。
- **状态机**：跳过支付/审核步骤、重放到终态、取消后继续、订单归属转移。
- **配额/试用**：重复注册、邮箱别名（`a+1@`）、邀请自邀、试用重置。
- **导出/报表**：范围参数（`from/to`）越界、分页越界、字段选择泄露。
- **GraphQL**：内省、批量查询、别名爆破、`__typename` 探测、嵌套深度 DoS（仅证明，不压垮）。

## 竞态（Race Condition）

- 单包并发：同一请求 20-50 份同时发出（Python `asyncio` + `aiohttp`，或用 `h2` 单连接多路复用）。
- 目标：余额扣减、优惠券核销、库存、邀请奖励、验证码校验。
- 判定：最终状态是否突破业务不变量（如余额为负、券超发）。
- 证据：并发脚本 + 最终 DB/接口状态截图 + 请求时间线。

## 证据要求

- A/B 两账号的请求与响应原文（脱敏），标明"谁的凭据、谁的对象"。
- 复现脚本（可直接跑），以及不变量被破坏的前后状态。
- 影响：可读取/修改的对象数量级、是否可自动化。

## 工具

`ffuf`（ID 枚举）· `python3 asyncio`（竞态/批量）· `curl` · Playwright（多会话）· `arjun`（隐藏参数）。
